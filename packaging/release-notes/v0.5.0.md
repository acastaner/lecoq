This release changes nothing about how lecoq looks or what it does. It is a tidy-up of the code
behind the scenes, so the app stays easy to change safely as it grows. Everything you open, save,
copy, move or annotate behaves exactly as it did in 0.4.0.

## Why a release with no visible changes

Software ages well only when the code underneath stays clear. This release acts on an architecture
review of the app and reorganises five areas that had grown awkward — not to add features, but to
make the next ones quicker to build and less likely to introduce bugs. We ship it on its own, and
say so plainly, so the history stays honest about what changed and when.

## What was tidied

- **Pop-up dialogs are handled in one place.** The "Save changes?", resize, overwrite, help and
  file-warning dialogs used to be tracked separately; they now share a single slot that guarantees
  only one is ever open at a time. This rules out a whole class of "two dialogs at once" bugs.
- **Annotation styles are defined once.** The list of style properties (colour, thickness, font and
  so on) was written out in several parallel places that had to be kept in step by hand. It is now
  declared once, so adding or changing a style option is a single, safe edit.
- **Each shape keeps its drawing and its size together.** How an annotation is drawn and how much
  of the picture it can cover used to live in separate files that had to be kept matching; they now
  sit side by side, so the two cannot drift apart.
- **Dead weight removed.** Four tiny, redundant source files were folded into where they belonged,
  and the shape-drawing code gained direct tests that previously could only be reached the long way
  round.

## No change to behaviour, speed or files

There are no new features, no changed shortcuts, and no change to how images are opened, saved,
copied, moved or annotated. Start-up and navigation speed are unchanged. The full automated test
suite passes exactly as before.
